# Universal AI Studio — macOS 原生多模态本地 AI 平台开发计划书

> **文档性质：** 产品规划与分阶段验收要求（供本地开发 Agent 执行）  
> **项目名称：** Universal AI Studio（暂定）  
> **目标平台：** macOS / Apple Silicon  
> **界面方向：** SwiftUI 原生应用，必要时使用 AppKit  
> **项目定位：** 统一部署、管理和运行本地 AI 模型的轻量化多模态工作台  
> **核心原则：** 原生、轻量、统一、开放、可扩展、高性能

## 0. 项目指令与范围

本计划书描述**要实现什么、按什么顺序推进、达到什么验收标准**，不约束具体代码组织、依赖版本、数据结构和底层实现细节。具体技术调查、方案选择、编码与验证由本地开发 Agent 负责。

该产品**不是 Codex、Claude Code 或 LingXiAgent 的替代品**。核心价值是统一模型管理、部署、推理与多模态交互；Agent 是按需启用的附加能力，普通推理不应依赖 Agent。

**首个正式版本的完整范围**包括：LLM、VLM、Embedding、Reranker、图像生成与编辑、ASR、TTS、视频生成、音乐／音频生成、轻量 Agent 和本地 API。各模态必须**从架构与交互规划阶段一起考虑**，可以分期交付真实功能，但不能以长期空白占位代替支持。

---

## 1. 总体目标

1. 一个 macOS App 管理不同来源、格式、架构和用途的本地模型。
2. 支持 Hugging Face 在线检索、**直接粘贴 Hugging Face 链接下载模型**，以及本地导入。
3. 支持可配置的**多线程／并发下载**，具备断点续传、重试、校验和可视化进度。
4. 通过多个推理后端覆盖 GGUF、MLX、Safetensors 及扩散等生态，避免绑定单一模型厂商或单一格式。
5. 统一管理模型生命周期、任务、参数、资源预算、存储和兼容性。
6. 为各模态提供符合其使用习惯的原生工作台。
7. 提供四工具起步、可通过 MCP／Skills／自定义工具扩展的轻量 Agent。
8. 提供按需开启的本地 API，供其他应用调用已支持的模型。
9. 让 App 的空闲开销、后台活动和运行时依赖尽可能低，优先把资源留给模型。

### 1.1 设计边界

**必须分清四个维度**：

| 维度 | 示例 | 目的 |
|---|---|---|
| 权重／存储格式 | GGUF、Safetensors、MLX 相关权重布局 | 识别模型文件及组成 |
| 模型架构 | Transformer、DiT、UNet 等 | 判断是否有兼容实现 |
| 任务类型 | Chat、Embedding、TTS、Video 等 | 决定交互与输入输出 |
| 推理运行时 | llama.cpp、MLX、Diffusers 生态等 | 执行实际计算 |

不能仅凭文件扩展名判断任务类型，也不能把“同一 App”误解为“所有模型必须运行在同一个引擎上”。

## 2. 开发与产品底线

### 2.1 macOS 原生体验

- 以 SwiftUI 为主，必要时配合 AppKit；遵循 Apple 人机界面规范。
- 完整支持亮／暗模式、系统强调色、键盘快捷键、窗口缩放、原生导航与状态反馈。
- 避免 Electron 或完整网页壳；不用大面积冗余装饰、过度动画替代功能体验。
- UI 美观、信息密度合理、操作路径短；界面性能不干扰模型推理。

### 2.2 运行轻量化

- 空闲时不加载模型；不运行无用的推理进程、MCP Server、Agent、监控轮询或下载任务。
- 未使用的运行时、扩展和 Python 依赖不应强制安装或常驻。
- 不重复下载、解压或保存相同权重；复用本地已有文件时应安全可靠。
- 支持模型卸载、任务取消及资源回收，并明确呈现占用和失败状态。
- 必须从项目初期建立应用空闲内存、CPU、启动时间等可重复的性能基线。

### 2.3 可靠性与安全

- 推理失败、模型格式不兼容、下载异常、工具运行失败都不应让主界面崩溃。
- 明确区分「已验证支持」「实验性支持」「未适配」「不兼容」。
- 用户文件访问、Shell 工具和外部扩展必须有清晰的授权边界。
- 模型及扩展来源应可见；涉及执行外部代码／不受信任资源时应提示风险。
- 不以 Mock、静态输出或仅有 UI 的页面冒充完成功能。

## 3. 统一模型管理中心

### 3.1 模型库

- 展示模型名称、来源、版本、类型、格式、参数量（适用时）、磁盘占用、运行状态。
- 支持本地文件／目录导入，扫描并识别已有模型及 Hugging Face 缓存。
- 识别模型目录中的配置、分片、Tokenizer、关联组件及必要的模型元数据。
- 支持模型分类、搜索、筛选、收藏、重命名显示名称和存储位置管理。
- 检查文件完整性、可用性、依赖要求与设备兼容情况。
- 对同一模型的不同格式、量化或版本建立关联，但不错误合并不同文件。
- 提供模型加载、卸载、切换、删除、迁移及错误说明。
- 管理删除操作时清楚告知共享缓存与其他模型的依赖关系，避免误删。

### 3.2 Hugging Face 模型下载中心（重点需求）

**核心用户场景：复制 Hugging Face 模型链接 → 粘贴到 App → 查看信息 → 选择需要的文件／版本 → 并发下载 → 校验 → 自动加入模型库。**

**链接与资源识别**

- 提供显眼的 HF URL 输入框，可粘贴 Hugging Face 模型仓库链接。
- 能理解常见仓库首页链接，以及指向特定文件、目录、分支／标签／提交版本的链接。
- 解析并展示模型名称、仓库、版本／revision、文件列表、总下载大小、所需磁盘空间与授权限制（可获取时）。
- 对仓库内包含不同量化、格式或多个子目录的情况，允许用户选择下载全部或指定文件组合。
- 自动识别模型运行所需的关联文件，降低漏下载配置、Tokenizer、权重分片等问题的概率。
- 明确提示私有仓库、受限（gated）模型、无权限或需要用户接受许可的情况；支持用户自行授权访问，安全保存凭据。

**多线程／并发下载**

- 必须支持**并发下载多个文件**；对于服务端允许分段请求的资源，支持**单文件分段并发下载**。
- 用户可调整并发数量，也提供稳妥的自动配置；避免高并发压垮磁盘、内存、网络或引发频繁限流。
- 支持任务队列、开始、暂停、继续、取消、优先级调整和失败重试。
- 支持断点续传，网络中断、App 重启后尽可能恢复任务，不无故重头下载。
- 显示总进度、单文件进度、实时速度、已下载量、预计剩余量及当前状态。
- 对限速、超时、链接过期、下载源不支持分段等情况给出合理降级和清晰报错。
- 下载结束后校验文件完整性；失败文件不得伪装成可加载模型。
- 下载前检查磁盘空间；避免重复下载已有且完整的文件。
- 下载完成后可直接进入模型详情和运行时兼容性检查。

**下载器体验要求**

- 将模型下载作为正式一级功能，而非隐藏在设置或终端命令里。
- 用户无需手动使用 `git lfs`、下载脚本或终端即可完成常见的 HF 模型下载。
- 下载任务与模型库状态联动；关闭窗口／切换页面不应导致无提示的数据损失。
- 提供可靠的异常提示与恢复入口，下载记录可追溯。
- 对可能需要专门的 Hub 文件传输机制的仓库，应正确适配，不能假定所有权重都是单个普通 HTTP 文件。

**验收场景**：从 HF 仓库首页链接下载一个多文件／分片模型；指定版本和文件集合；调整并发数；模拟断网与重启并恢复下载；校验结果并在模型库中加载。至少应覆盖公开模型与需要授权的模型各一种；无法取得测试权限时须如实标明未验证。

## 4. 多推理运行时与统一任务管理

- 接入适用于 GGUF、MLX、Diffusion 等模型生态的多个后端；其他框架可持续扩展。
- 不要求所有模型使用相同权重格式，也不承诺任意 Hugging Face 仓库都能直接运行。
- 统一呈现模型兼容性、运行时可选项、加载／卸载、推理状态和错误。
- 根据模型能力显示相应参数，不对不支持的参数提供无效控件。
- 统一管理耗时任务的排队、并发、取消、进度、结果和输出路径。
- 运行失败不应牵连无关模型或使 App 无法继续使用。
- 支持推理前的内存需求提醒与运行过程资源观测。
- 支持第三方应用通过统一接口调用已加载的模型。

## 5. 多模态功能清单

> 每一类模态都必须具备**真实可运行**的最小端到端流程；统一设计规范，但不强求共用同一操作页面。

### 5.1 LLM：文本对话

- 多轮聊天、流式输出、会话历史、模型切换。
- Temperature、Top-P、上下文长度等模型适用参数。
- 模型支持时展示推理／思考内容与工具调用状态。
- 提示词、Chat Template 兼容性及生成统计（Tokens、速度、延迟）。

### 5.2 VLM：视觉理解

- 图片／多图片输入、图文问答、图像内容分析与 OCR 类场景。
- 支持模型具备的视频理解输入。
- 与 LLM 对话工作台自然融合，不重复开发一套聊天系统。

### 5.3 Embedding / Reranker

- 文本向量生成、批量生成、向量维度及导出。
- 支持模型具备的图片／跨模态 Embedding。
- 语义相似度对比、Reranker 排序测试及 API 调用。

### 5.4 图像生成与编辑

- Text-to-Image、Image-to-Image、图像编辑。
- 模型支持时提供分辨率、Steps、Guidance、Seed、Sampler、LoRA 等参数。
- 生成预览、历史、参数复用、任务管理、结果导出。

### 5.5 ASR：语音识别

- 音频导入、转录、多语言和自动识别（模型支持时）。
- 长音频、时间戳、文本编辑、字幕导出、批量任务。

### 5.6 TTS：语音合成

- 文本转语音、多语言、音色选择、适用参数调整。
- 模型支持时提供参考音频和声音克隆。
- 试听、批量合成、历史和音频导出。

### 5.7 视频生成

- Text-to-Video、Image-to-Video。
- 模型支持时提供时长、分辨率、帧率等配置。
- 进度、队列、视频预览／播放、导出与历史管理。
- 对超出设备能力的模型给出明确提示，避免无意义尝试导致严重 Swap。

### 5.8 音乐／音频生成

- Text-to-Music、模型支持的续写及条件生成。
- 音乐长度、提示词、模型适用参数、波形／试听、输出管理。
- 与 ASR/TTS 共用整体视觉规范，但维持独立任务交互。

## 6. 轻量 Agent 系统

**定位：** 可选、低开销的小模型 Agent 工作模式；不开启 Agent 时不增加普通推理负担。

### 6.1 四个基础工具

| 工具 | 功能 |
|---|---|
| `read` | 读取被授权的文件／内容 |
| `write` | 创建或覆盖被授权文件 |
| `edit` | 对被授权文件进行精准修改 |
| `bash` | 在明确授权边界内执行命令 |

### 6.2 扩展能力

- MCP Server 接入与启停。
- Skills 安装、发现与按需加载。
- 自定义工具／扩展的启用、禁用和权限管理。
- 执行日志、调用状态、错误解释和用户确认机制。

### 6.3 小模型开销控制

- 以极简系统提示词和固定基础工具为默认配置。
- 扩展工具的描述和 Schema 按需提供，不一次性塞入全部上下文。
- 工具结果长度受控；大结果可分页／引用／摘要。
- 观测 System Prompt、Tool Schema、工具结果与历史上下文各自的 Token 开销。
- 控制 Agent 循环轮数、失败重试、无效重复调用和超时。
- 提供「纯聊天」「Agent」「扩展 Agent」等清晰运行模式。

## 7. 本地 API 与第三方调用

- 已支持的 LLM、VLM、Embedding、Reranker、图像、ASR、TTS、视频、音乐任务均应有可调用接口。
- 优先兼容常见开放接口习惯，并为各模态特有能力补充统一管理接口。
- API 服务可手动启停，不应成为 GUI 或单机推理的强制依赖。
- 支持任务状态、错误反馈、模型切换、并发限制和请求记录。
- 对本机／局域网访问范围和权限作清晰区分，避免未经授权的模型服务暴露。

## 8. UI / UX 体验规划

### 8.1 导航与工作区

建议的功能结构如下，允许本地 Agent 基于 macOS 体验进一步优化：

- **模型库**：全部模型、兼容性、加载状态、存储占用。
- **下载中心**：Hugging Face 链接输入、文件选择、并发任务、速度／进度。
- **对话**：LLM / VLM。
- **图像**：生成与编辑。
- **音频**：ASR、TTS、音乐生成，入口明确分区。
- **视频**：生成和预览。
- **向量**：Embedding / Reranker 测试。
- **Agent**：轻量任务对话、工具调用和扩展管理。
- **运行状态**：模型占用、任务、资源压力、错误与日志。

主窗口可以使用系统 Sidebar + 工作区 + 可收起 Inspector 的原生布局。下载中心、任务列表与模型状态需要跨页面保持一致。

### 8.2 视觉与交互验收

- 视觉精致、克制，支持浅色与深色主题。
- 模型下载、启动、推理、导出这些高频动作清晰可发现。
- 每类工作区对其输入／输出形式进行原生优化：聊天、图像画布、音频试听／波形、视频播放器、向量结果等。
- 参数区只显示当前模型真正支持的配置项。
- 支持窄窗口、辅助状态提示、键盘操作和自然的多任务切换。
- 不使用高频无意义动画或重型渲染来追求视觉效果。

## 9. 性能、资源与电源管理

- 建立 App 空闲／运行模型时的内存、CPU、GPU、启动时间和任务延迟基线。
- 明确区分 App 本体、推理运行时和模型权重的资源占用。
- 关注内存压力与 Swap，提示潜在超限并提供合理的加载建议。
- 支持模型卸载、闲置释放、任务取消与资源回收。
- 针对 16GB、24GB、32GB 及更高内存的 Apple Silicon 设备测试典型使用路径。
- 感知电池与外接电源状态，允许控制后台高负载操作。
- 无用户发起的任务时不进行持续高负载计算。

## 10. 开发阶段与验收

### Phase 0 — 初始化仓库与原生工程（**第一优先级**）

- 创建 Git 仓库。
- 建立 SwiftUI macOS App 工程，完成应用启动、窗口显示和退出。
- 确认 Apple Silicon 开发环境，形成基础文档、构建／测试规范。
- 打通 Debug / Release 构建与最基础的 CI 检查。
- 记录原生空项目的启动、空闲内存和 CPU 基线。
- 提交初始化版本。

**验收：** 干净环境可构建、启动和退出，Git 记录与基础工程规范完整，无不必要的重型依赖。

### Phase 1 — 完整产品框架与交互基础

- 规划全部模态、模型库、下载中心、Agent、API、任务管理的功能边界。
- 完成原生窗口、导航、主题、参数区、任务状态等基础 UX。
- 确立模型／运行时／任务的统一管理要求，避免后续加模态时冲突。
- 建立资源观测与错误反馈的整体产品规范。

**验收：** 全部模块的职责和操作路径清楚；页面可进入但未实现的功能必须明确标记，不得假装可用。

### Phase 2 — 模型库、HF 高并发下载与首批推理

- 完成模型扫描、导入、识别、存储管理与兼容性信息。
- **完成粘贴 HF 链接下载模型**，支持文件／版本选择。
- **完成可配置多线程／并发、任务队列、暂停恢复、断点续传、重试、校验。**
- 完成首批真实后端接入、模型加载／卸载、模型状态和运行失败反馈。

**验收：** 从 HF 链接下载真实分片模型，完成可恢复的并发下载与校验，并通过 GUI 在兼容后端中加载与推理；本地已有模型可导入复用。

### Phase 3 — 全模态真实推理

逐项打通并测试：

| 方向 | 最小真实验收 |
|---|---|
| LLM | 模型加载、流式对话、多轮历史 |
| VLM | 图片输入与模型实际视觉回答 |
| Embedding | 真实向量计算与结果展示 |
| Reranker | 输入候选文本并得到真实重排序 |
| 图像生成 | 真实生成图片 |
| 图像编辑 | 真实完成受支持的编辑任务 |
| ASR | 真实音频转录 |
| TTS | 真实生成可播放语音 |
| 视频生成 | 真实生成并播放视频 |
| 音乐生成 | 真实生成并试听音频 |

**验收：** 各模态至少具备一条经过验证的端到端模型路径，不以模拟输出或空页面代替完成。

### Phase 4 — 轻量 Agent 与扩展生态

- 实现四个基础工具及权限／确认／日志。
- 完成 MCP、Skills、自定义工具按需管理。
- 控制上下文、工具 Schema 与结果开销。
- 使用真实本地小模型验证调用成功率与任务完成情况。

**验收：** Agent 可完成有限权限内的真实工具任务，能够观测自身开销；Agent 不启用时不影响普通模型工作台。

### Phase 5 — 统一 API

- 为已支持模态提供第三方调用能力。
- 支持按需启停、任务状态、错误、模型选择与并发限制。
- 测试真实第三方客户端调用。

**验收：** 第三方程序可以稳定调用至少一条已验证的各模态推理路径。

### Phase 6 — 性能、稳定性与完整体验优化

- 持续降低应用本体空闲资源、无效后台任务与界面开销。
- 优化模型切换、加载／卸载、下载与推理任务管理。
- 完成断网、空间不足、取消、崩溃、OOM 风险、权限不足等异常场景测试。
- 完成全部模态 UI 的一致性、可达性、暗色模式、窗口尺寸和交互体验检查。
- 提供稳定的资源数据与性能对比结果。

**验收：** 模型运行流畅可靠，App 本体维持轻量，长时间使用无明显泄漏或不可恢复错误。

### Phase 7 — 正式发布

- 完成全功能回归、真实模型兼容性矩阵、许可／依赖审计。
- 完成应用图标、首次使用引导、帮助文档、签名及发布准备。
- 整理已知问题和正式版本发布说明。

**验收：** 目标模态真实可用，文档与兼容性声明符合实际，发布包可在目标 macOS 环境正常运行。

## 11. 本地开发 Agent 执行规则

1. **先完成 Phase 0。** Git 仓库与 SwiftUI 工程成功建立后再推进其他阶段。
2. Agent 可自行决定技术实现、调研框架并细化任务，但不得擅自缩减既定产品范围。
3. 每个功能必须有可复现的验证方法；编译成功不等于功能完成。
4. 不以 Mock、硬编码、静态 UI 冒充真实推理或下载功能。
5. 优先可维护、低依赖、可按需运行的方案，避免“一装就带全家桶”。
6. 每个阶段进行回归检查，新增模型或运行时不能破坏已有流程。
7. 有意义的里程碑必须提交 Git，提交记录能够对应功能与测试结果。
8. 无法完成的能力需清楚记录原因、设备限制、当前状态和后续条件。
9. 不得擅自对外发布模型服务、读取不相关隐私文件或降低工具执行权限边界。
10. UI 设计与性能优化从初期同步推进，而不是开发末期集中返工。

## 13. 最终产品愿景

让用户通过**一个轻量、美观的 macOS 原生应用**，完成本地模型的**发现、Hugging Face 链接高速下载、部署、配置、运行、调用及管理**。

无论是聊天、图像、语音、视频、音乐、Embedding，还是轻量 Agent 工作流，都共享一致的管理和资源调度体验，却不必被迫运行在单一框架之上。

**衡量产品价值的关键指标：** 支持模型的广度、模型运行的可靠性、一键部署的实际成功率、下载体验、原生 UI 品质，以及 App 自身足够低的系统开销。
