# 分步实施与验收

日期：2026-10-15。需求基准：[产品计划书](AA/Universal_AI_Studio_Project_Plan.md)。执行环境与命令：[开发环境](Development_Environment.md)。

## 执行规则

先完成 Phase 0，再推进功能。下文是实施顺序，不是完成声明；当前工程要求 macOS 26.2+、仅 arm64，稳定 Xcode 优先，macOS 27 持续做兼容验证。初始证据见 [Phase 0 本地验收](Verification/Phase_0_Local.md)，本轮状态见 [收尾与 CI](Verification/Phase_0_Closeout.md)，四层测试规则见 [测试体系](Testing.md)。没有用空页面、静态结果或 Mock 代表模态已实现。

每个编号都是可单独验收的工作单元：先完成“干什么”中的交付物，再逐项执行“如何验收”。不通过就记录原因和恢复条件，不进入依赖它的步骤。允许互不依赖的步骤交错开展，但不提前缩减首版范围。

每一步在 `Docs/Verification/Step_<编号>.md` 留存：日期、Git commit、设备／内存、系统／工具链、前置条件、操作或命令、预期／实测、结果、证据路径、已知限制与复测条件。真实模型还须记录仓库、固定 revision、文件清单／校验、运行时及版本、量化／参数、输入／输出、耗时和资源数据。截图不能替代执行日志；凭据、用户隐私与带 token 的 URL 不进入记录。临时日志、模型样本和调试脚本留在 `.tmp/`，大模型权重不入 Git。

状态统一为：`待实施`、`进行中`、`通过`、`失败`、`未验证（说明条件）`。只有正常路径、该步列明的异常场景和回归均通过才能标为通过。缺设备／授权的项目必须标未验证，不能用“理论支持”补齐。

新增工具、依赖、运行环境或服务须先获许可；安装前检查来源、版本、许可证和执行边界，不自动运行 HF 仓库中的远程代码。原始计划书保留，不用此文档覆盖或改写需求。每个有意义的里程碑通过验收后提交 Git，commit message 使用英文。

## Phase 0：工程与开发基线

### 0.1 核查工具链与初始化仓库

**干什么：** 核查 macOS／arm64、Xcode、Swift、SDK、Git；建立 Git 仓库、忽略规则、README 和开发环境文档。最低系统正式设为 macOS 26.2+、仅 arm64，不兼容 macOS 14／15／26.0／26.1；稳定 Xcode 优先，macOS 27 另做兼容验证。

**如何验收：** 执行开发环境文档中的版本命令，结果可复现；`git status` 正常；构建、缓存、凭据不会进入待提交文件；另一位开发者能找到构建、启动、检查入口。不得安装计划外依赖或读取凭据。

**交付证据：** 环境表、仓库初始状态、忽略规则检查。

### 0.2 建立可启动的原生 App

**干什么：** 建立 SwiftUI 入口、macOS 窗口、bundle 元数据及 Debug／Release 构建打包流程。初始化窗口明确标注当前尚无推理功能，不做产品功能假演示。

**如何验收：** 两种配置均编译、plist／签名校验通过；Package.swift、plist 与真实 Mach-O minos 均为 26.2，二进制仅含 arm64；Finder 打开 App 后能看见原生窗口与文字；可缩放，关闭后可重新打开，Command-Q 正常退出且无遗留进程。macOS 27 本机验证，精确 macOS 26.2 实机行为另列硬件验收，不以修改文档替代产物检查。

**交付证据：** 构建命令、窗口截图、启动退出记录、支持边界。

### 0.3 建立检查入口并接入 CI

**干什么：** 接入 GitHub Actions `macos-26` arm64 Runner 与稳定 Xcode，Push／Pull Request 自动触发；干净解析依赖，执行所有当前适用的 Python／Swift 单元测试、Debug／Release 构建、真实产物部署目标检查；保存失败日志和测试报告。分层推进真实推理／GPU／全模态测试，不提前开发后续功能。

**如何验收：** 本地检查返回 0；错误参数、旧最低系统或 Intel／通用产物被拒绝。远程 CI 的干净依赖解析、全部当前适用测试与两种构建实际通过，提供对应 commit／运行链接和产物报告；报告区分通过、失败、跳过与尚未覆盖，任何实际失败不得伪装通过。模型／下载／任务／API 尚未实现的模块只记未覆盖。

**交付证据：** 本地测试结果、远端成功运行链接或明确待办。

### 0.4 测量空工程并提交初始化里程碑

**干什么：** 在 Release 下建立启动、空闲 CPU／内存基线；记录测量口径和设备；完成初始化 Git 提交。

**如何验收：** 依开发环境文档重复测量至少 3 次，每次预热 5 秒、采样 30 秒；保存初始基线与同硬件环境的新结果，记录 CPU／RSS／启动及未实现的模型指标；不将根视图回调时间当首帧，不将共享 Runner 速度当正式基准。确认没有模型、API、MCP 常驻；完成 Git 提交。Phase 0 CI 收尾需要 0.3 的远程成功证据；真实 GPU／全模态随功能阶段补齐，未执行不能标通过，也不阻塞 Phase 1。

**交付证据：** 基线表、测量方法、commit、未验证清单。

## Phase 1：完整产品框架

依赖：Phase 0 的本地工程与检查入口；远端 CI 尚未完成时须持续标明。

### 1.1 定义全模态边界与数据契约

**干什么：** 分开建模存储格式、模型架构、任务类型、运行时；定义模型身份／revision／组件、兼容性、任务状态、输入／输出、参数能力、错误与取消契约。覆盖模型库、下载、聊天／视觉、向量／排序、图像、ASR／TTS／音乐、视频、Agent、API，先写契约与少量真实用例，不为每个模态复制调度器。

**如何验收：** 同为 Safetensors 的聊天与图像模型不会被误认成同一种任务；同模型的量化版本可关联而不合并文件；未知模型不会默认判“支持”；每个目标模态都能对应输入／输出和运行时候选。契约的合法／非法状态转换有小型测试。

**交付证据：** 能力矩阵、数据／状态说明、契约测试。

### 1.2 建立原生导航与工作区交互

**干什么：** 建立 Sidebar、工作区、参数区与跨页任务状态；为所有模态规划操作路径。优先系统控件，支持主题、强调色、快捷键、窗口缩放；未实现项明确显示状态，不出现无效的“运行成功”。

**如何验收：** 所有入口可理解并能定位职责；切换页面不丢任务；亮／暗模式、窄窗口、键盘导航及 VoiceOver 标签可用；模型未支持的参数不显示成可用；原型状态不被写入兼容性矩阵为“通过”。

**交付证据：** 各入口截图、键盘／主题检查表、未实现标识记录。

### 1.3 建立统一任务与错误反馈

**干什么：** 实现排队、运行、取消、成功、失败的统一状态及任务标识；结果持久化、错误恢复入口和输出路径管理。不执行任务时不轮询或拉起后端。

**如何验收：** 对可控本地任务验证排队、取消竞态、重复取消、失败、重启后的恢复语义；一个任务异常不影响无关任务；取消后不再追加成功结果且释放资源。测试替身仅验证调度逻辑，不作为真实推理证据。

**交付证据：** 状态转换测试、错误／取消操作录像或日志。

### 1.4 建立资源预算与权限规范

**干什么：** 统一显示 App／运行时／权重占用，设计内存压力、Swap、磁盘不足和电源状态的提示与决策；定义用户选取目录、书签、Shell、扩展和局域网访问边界。

**如何验收：** 资源采样不会造成持续高负载；关闭页面后不遗留重复观察器；低资源时可取消／拒绝运行；拒绝文件授权后给出可恢复错误；权限矩阵覆盖所有入口，不存在普通聊天隐式取得 Shell 权限。

**交付证据：** 权限矩阵、资源显示口径、空闲基线对比。

## Phase 2：模型库、HF 下载与首批推理

### 2.1 本地模型识别与安全导入

**干什么：** 支持文件／目录导入、用户授权范围内扫描、HF 缓存识别、配置／Tokenizer／分片／关联组件检查；记录来源、格式、任务、大小、版本与文件完整性。支持搜索、分类、筛选、收藏、显示名修改。

**如何验收：** 导入真实单文件与分片模型；缺配置／分片、未知架构、无权限均有明确状态；相同文件复用且不复制整套权重；不跟随恶意路径逃逸授权目录；重启后元数据和用户设置一致。

**交付证据：** 样本清单、识别结果、异常测试与持久化结果。

### 2.2 模型存储、迁移与删除

**干什么：** 区分 App 自有文件、用户原文件和共享缓存；建立引用关系、迁移／删除预览与确认流程。删除共享内容前明确受影响模型，迁移前检查空间并保留可恢复原件。

**如何验收：** 两个模型共享文件时删除其中一个不损伤另一个；仅移除索引不误删用户原件；迁移中断可恢复，校验通过前不切换到新位置；空间不足不破坏旧数据。破坏性验收只使用专用样本和备份。

**交付证据：** 删除／迁移前后文件清单、引用检查和中断恢复记录。

### 2.3 HF 链接解析、授权与文件选择

**干什么：** 建立一级下载中心，解析仓库首页、文件、目录、branch／tag／commit 链接；获取文件树、大小、许可限制，固定实际 revision，自动建议关联组件。私有／gated 权限由用户在授权流程处理，凭据安全保存，不进日志。

**如何验收：** 使用仓库／blob／resolve／tree 链接及包含特殊字符的 revision 验证；无法无歧义拆分时通过服务端信息或用户选择确认；拒绝非法 URL、路径穿越和不允许的来源；公开、401／403、许可未接受均有区分；文件集合与总大小和服务端元数据一致。实际授权模型未取得权限则记未验证。

**交付证据：** 脱敏 URL 用例表、固定 revision、文件选择与授权状态。

### 2.4 可靠单文件传输与断点恢复

**干什么：** 先完成临时文件、安全落盘、超时、取消、重试和断点元数据；验证服务端 Range、ETag／Last-Modified／版本一致性；处理普通 HTTP、重定向、签名链接过期和 Hub 专门传输路径，不假定所有资源都是普通直链。

**如何验收：** 本地可控 HTTP 服务覆盖 206／正确 Content-Range、忽略 Range 返回 200、416、内容变化、过期链接、429／Retry-After、超时／断网；恢复不能拼接不同版本或将 HTML 错误页当权重。真实 HF 样本走通对应路径；专门传输机制未适配时明确拒绝或合法降级。

**交付证据：** 传输回归、网络中断恢复记录、临时／完成文件状态。

### 2.5 多文件与单文件分段并发

**干什么：** 在可靠传输上加入可调全局／单任务并发、任务优先级、自动保守配置；服务端支持时分段下载同一文件，限制磁盘／内存和限流。提供总／单文件进度、速度、下载量与合理 ETA。

**如何验收：** 至少两个文件真实并行；支持 Range 的大文件至少两个分段并行且合并校验一致；不支持时自动退回可靠单流；运行中调整并发后实际连接数符合上限；重叠／缺失分段、暂停／取消、429 不会损坏文件或失控重试。ETA 数据不足时显示未知。

**交付证据：** 并发配置、实际连接／任务日志、分段合并校验与降级结果。

### 2.6 队列持久化、校验与自动入库

**干什么：** 完成开始／暂停／继续／取消／重试、优先级、App 重启恢复、下载记录；下载前检查空间、复用完整已有文件，完成后校验并原子入库。使用仓库可验证的哈希或内容标识，不把任意 ETag 当 SHA-256。

**如何验收：** GUI 从 HF 首页选定 revision／文件集下载真实分片模型；断网、关闭窗口、退出并重启后可恢复；校验失败不能标可加载；空间不足、已有损坏文件与磁盘写入失败均清晰反馈。公开与授权模型各一条真实链路；缺权限的条目保持未验证。

**交付证据：** 完整下载恢复录像／日志、哈希与入库记录、授权覆盖情况。

### 2.7 首批真实运行时与生命周期

**干什么：** 调研并经许可引入首个最小后端，接通能力探测、加载、卸载、参数、流式输出、取消、错误和资源预算。GGUF／MLX／扩散生态各自评估，不根据扩展名承诺兼容；可选后端按需安装／启动。

**如何验收：** 通过 GUI 加载 2.6 下载的兼容模型并得到真实输出；本地导入模型也能运行；不兼容模型解释原因；卸载和任务取消后观察内存／进程回落；后端崩溃后 GUI 可继续用，普通 App 启动无后端常驻。首批成功不代表多后端覆盖完成。

**交付证据：** 固定模型与后端版本、真实输入／输出、生命周期和崩溃恢复记录。

## Phase 3：逐模态真实推理

每一步依赖 1.1、1.3、2.7；需要的可选运行时必须先完成来源／许可证／版本核验和安装许可。每个模态至少选择一个在目标设备可运行的固定模型路径；不虚构统一后端，不提前锁定未经验证的模型。

### 3.1 LLM 文本对话

**干什么：** 实现流式多轮聊天、历史持久化、模型切换、Chat Template／Tokenizer 处理、适用采样参数、tokens／速度／首 token 延迟；支持时分开展示思考和工具调用状态。

**如何验收：** 真实模型回答固定问题，多轮能引用前文，流式逐步到达；重启恢复历史；切换模型使用其模板和能力；停止后输出结束、上下文不污染；模板不兼容／上下文超限有错误。导出统计能对应真实 token／时间口径。

**交付证据：** 对话、模板／参数、流事件、历史与取消验证。

### 3.2 VLM 视觉理解

**干什么：** 复用对话工作台，支持单图／多图、图文问答和 OCR 类输入；模型确实支持时再接视频理解，不将文件附件名称当视觉输入。

**如何验收：** 提交内容不同的真实图片，输出正确区分可见信息；日志证明后端收到图像数据；坏图、超限与取消可恢复；多图能力按模型声明验证。支持视频理解的路径需另测视频内容，未支持时明确不提供入口。

**交付证据：** 测试图片来源、后端输入证据、回答与能力边界。

### 3.3 Embedding

**干什么：** 实现单条／批量文本向量、维度显示、导出与相似度；模型支持时加入图片／跨模态向量，复用任务与批量取消机制。

**如何验收：** 真实模型生成向量，维度与配置一致，值有限且非空；近义文本相似度高于明显无关文本；批量保留输入对应关系，导出可读取。跨模态路径单独记验证状态。

**交付证据：** 输入／实际向量、维度、排序对照和导出文件。

### 3.4 Reranker

**干什么：** 输入 query 与候选文本，输出真实评分、排序与原索引，保留适用参数及错误反馈。

**如何验收：** 固定相关／无关候选由真实模型评分；排序对应原文本且分数有限；空候选、重复候选、长文本和批量取消有稳定行为，不用 Embedding 相似度假冒 Reranker。

**交付证据：** query、候选、真实评分与索引回归。

### 3.5 图像生成

**干什么：** 完成 Text-to-Image、预览、历史、导出、参数复用；按模型能力提供分辨率、Steps、Guidance、Seed、Sampler、LoRA，缺能力时不显示无效项。

**如何验收：** 从文字真实生成可解码图片，尺寸与请求相符；参数／seed／运行时与结果关联；LoRA 仅对已验证组合开放；取消、资源超限、错误后下一任务仍能运行。GPU 非确定性时记录误差与复现边界，不承诺字节一致。

**交付证据：** 原图、生成参数、任务日志与资源占用。

### 3.6 图像编辑

**干什么：** 打通 Image-to-Image 和至少一种后端支持的真实编辑路径，管理原图／蒙版／提示词与输出，不覆盖原始输入。

**如何验收：** 用有明确目标的样本真实编辑；结果既反映编辑目标又保留需要保留的内容；坏图／不匹配蒙版明确失败；原图校验值不变，历史可复用参数并导出。模型不支持的编辑类型明确标注。

**交付证据：** 编辑前后样本、输入校验、模型能力与实际效果。

### 3.7 ASR

**干什么：** 音频导入、转录、适用语言／自动语言识别、长音频、时间戳、编辑、字幕导出和批量任务。

**如何验收：** 固定带人工稿的短／长音频真实转录，记录识别误差；时间戳单调且处于音频时长范围，字幕可被播放器读取；静音、坏文件、取消和多任务不会串结果。语言覆盖以实测矩阵为准。

**交付证据：** 音频／人工稿来源、转录、字幕与误差记录。

### 3.8 TTS

**干什么：** 文本合成、适用语言／音色／参数、试听、批量、历史与导出；仅在模型支持并具备授权样本时提供参考音频／声音克隆。

**如何验收：** 固定文本真实生成非静音、可解码播放的音频，人工试听内容／读音；验证多语言／音色的已支持组合；声音克隆使用明确授权样本独立验收；空文本、过长文本、取消不产生伪成功记录。

**交付证据：** 文本、音频、实际音色／参数、试听记录和能力边界。

### 3.9 视频生成

**干什么：** Text-to-Video、Image-to-Video、能力允许的时长／分辨率／帧率、进度／队列、播放器、历史和导出；运行前估算资源。

**如何验收：** 两种输入分别真实生成并播放视频；帧数、时长、尺寸符合后端允许范围；队列和取消可用；设备承载不了时提前说明并拒绝不合理任务，不能靠严重 Swap 勉强判通过。只有高内存设备通过时明确限定设备档位。

**交付证据：** 输入、视频、媒体元数据、设备资源和两条模式结果。

### 3.10 音乐／音频生成

**干什么：** Text-to-Music、长度与适用提示／参数、波形／试听、历史／导出；模型支持时加入续写／条件生成，保持独立工作流并复用音频播放基础能力。

**如何验收：** 文本真实生成非静音可播放音频，时长符合模型允许范围，人工确认不是 TTS 或预置片段；续写／条件模式单独验收；并发、取消和坏输入正常，不覆盖原始音频。

**交付证据：** 输入、生成音频／时长、试听记录和扩展模式状态。

### 3.11 多运行时覆盖与回归

**干什么：** 汇总 GGUF、MLX、扩散及其他必要后端的真实支持矩阵，按模型任务和固定版本管理。不同后端的错误、参数和资源生命周期接回统一契约。

**如何验收：** 至少覆盖 GGUF／MLX 和全模态所需后端；上述十类方向均至少有一条真实端到端路径；一个后端失败不影响另一个，新增后端后旧模态回归通过；未知／实验／已验证／不兼容四状态清楚。

**交付证据：** 兼容性矩阵、后端版本／许可证和跨模态回归结果。

## Phase 4：轻量 Agent 与扩展

### 4.1 四个工具与文件／Shell 授权

**干什么：** 在纯聊天之外加入可选 Agent 模式，实现 `read`、`write`、`edit`、`bash`，限定目录、命令和确认边界；写覆盖／删除前保留可恢复数据，记录真实 ToolResult 与错误。

**如何验收：** 专用临时工作区中完成读取、创建、精准修改和有限命令；拒绝路径穿越／符号链接逃逸／未授权命令；不匹配 edit 不误改；拒绝确认后无副作用；模型声称成功不能替代文件差异或实际工具结果。

**交付证据：** 权限与工具回归、前后文件校验、脱敏执行日志。

### 4.2 Agent 循环与真实小模型

**干什么：** 实现工具调用编排、超时、轮数／重试／重复调用上限、取消和上下文管理；用真实本地小模型评估有限任务完成情况。

**如何验收：** 固定任务集真实完成，报告分母／成功数／失败原因；错误工具参数、超时、重复调用能终止；取消时待确认请求和后台任务结束；重启后不自动重放副作用。

**交付证据：** 模型／任务集、实际成功率、异常与取消记录。

### 4.3 MCP、Skills 与自定义扩展

**干什么：** 接入按需安装／发现／启停的 MCP Server、Skills 和自定义工具，显示来源和权限；新进程不继承无关凭据，扩展内容作为不可信输入处理。

**如何验收：** 可信测试扩展可启用、调用、关闭；错误 Schema、Server 崩溃、超时、超长输出均可恢复；禁用后进程／连接确实释放；扩展不能提升已授予的目录／命令权限；安装外部代码有明确确认。

**交付证据：** 扩展样本、生命周期、拒绝与故障恢复日志。

### 4.4 上下文开销与关闭状态验收

**干什么：** 区分纯聊天／Agent／扩展 Agent；按需提供工具描述，限制结果长度，记录 system／schema／历史／结果的 token 开销。

**如何验收：** 相同模型／提示下比较三种模式；纯聊天无 Agent 循环和扩展进程；不开启扩展不注入其完整 Schema；大结果可分页或引用，计数不可获取时标估算及算法；停用后空闲资源回落。

**交付证据：** token 分项、模式对照、进程和资源采样。

## Phase 5：统一本地 API

### 5.1 API 生命周期与安全访问

**干什么：** 建立手动启停服务，默认仅 loopback；区分本机／局域网权限，明确认证、并发、大小限制、错误语义和请求记录；GUI 不依赖服务运行。

**如何验收：** 默认无监听；开启后仅绑定明确的本机地址，停用后端口释放；未获授权不绑定局域网／公网；无效认证、超大请求、端口冲突正确处理；日志无凭据和敏感正文泄漏。

**交付证据：** 真实监听地址、启停／拒绝测试、访问控制记录。

### 5.2 已实现模态的 API 与任务接口

**干什么：** 按已实现能力提供模型选择、同步／流式／异步任务、状态／取消／结果接口；可兼容的部分遵循常见开放接口，扩展接口清楚记版本与 Schema。

**如何验收：** 对 3.1–3.10 每一类已通过路径用外部客户端发送真实请求并取得相应文本／向量／图像／音视频；模型切换、错误、断连取消、队列与并发语义和 GUI 一致；不接受未实现能力后返回伪结果。

**交付证据：** 脱敏请求／响应、任务状态与媒体文件、接口说明。

### 5.3 第三方集成与 GUI 并存

**干什么：** 选择至少一个现有第三方客户端验证兼容接口，其余模态提供可直接执行的标准库客户端样例；统一 GUI 与 API 的模型和任务资源预算。

**如何验收：** 第三方客户端真实调用成功；API 和 GUI 同时提交任务时遵守同一并发／内存预算，取消互不误伤；服务停用后 GUI 仍可独立推理。不能把 App 内部单元测试作为第三方验收。

**交付证据：** 客户端／版本、调用结果、混合负载回归与样例。

## Phase 6：稳定性、性能与体验

### 6.1 故障恢复回归

**干什么：** 统一验证断网、限流、空间不足、权限拒绝、进程崩溃、取消竞态、App 意外退出、模型损坏和 OOM 风险；破坏性测试只用隔离样本／受控故障注入。

**如何验收：** 下载可恢复且不误报校验通过；推理／工具／API 故障不导致 GUI 不可恢复；有持久化数据不丢失／不重复执行副作用；禁止用真实主机耗尽内存／磁盘的方式验证边界。

**交付证据：** 故障矩阵、恢复操作、前后数据与回归结果。

### 6.2 设备分档与资源回收

**干什么：** 对 16／24／32 GiB 及更高内存 Apple Silicon 建立适配档位，分别测 App、后端、权重、GPU／内存压力／Swap；比较加载、推理、切换、卸载、取消、闲置释放与电源策略。

**如何验收：** 同设备／构建／模型／参数重复测量，报告中位数与波动；卸载／取消后资源回落，任务结束无孤儿进程；低内存机能合理拒绝超限模型；未拿到的设备明确未验证，不外推本机结果。

**交付证据：** 档位矩阵、Phase 0 对比、时序采样及限制。

### 6.3 长时间稳定性

**干什么：** 固定至少 2 小时交替执行下载、各模态任务、模型切换／卸载与取消；保留运行期间内存与错误轨迹，明确采样间隔和任务次数。

**如何验收：** 无崩溃、数据损坏和不可恢复状态；内存无持续不可解释增长；后半段任务仍能完成；发现问题给出复现与修复后复测记录。2 小时是首轮工程门槛，不代表无限运行保证。

**交付证据：** 长测场景／次数、资源曲线、异常与恢复结果。

### 6.4 原生 UI 与辅助功能

**干什么：** 全工作区检查暗色／浅色、强调色、窄窗口、长文本、动态状态、键盘、VoiceOver、减少动态效果与高对比度；保持参数和实际能力一致。

**如何验收：** 核心流程可用键盘完成，控件有可读名称，媒体能预览／导出；无截断关键操作、焦点陷阱、失效参数或高频无意义动画；切页／关窗不无提示丢任务。

**交付证据：** 各工作区／主题／窗口尺寸检查表与问题关闭记录。

## Phase 7：正式发布

### 7.1 首版范围与许可核对

**干什么：** 将产品计划书第 12 节逐项映射至通过的步骤、真实模型与设备；核对依赖／模型／扩展许可证和分发条件，冻结兼容性矩阵和已知问题。

**如何验收：** LLM、VLM、Embedding、Reranker、图像生成／编辑、ASR、TTS、视频、音乐、Agent 扩展、本地 API 均有真实证据；HF 并发恢复与多后端无遗漏；正式版必需能力缺失则不能宣称范围完成，不能通过把条目标“实验”绕过门槛。

**交付证据：** 首版需求追踪表、兼容性矩阵、许可证清单与阻塞项。

### 7.2 分发工程、签名与首次使用

**干什么：** 完成正式 bundle identifier、图标、帮助／引导；评估并落实 Xcode App target、entitlement、可选运行时分发、Developer ID 签名与公证。签名凭据由用户或授权系统管理，不能读取私密配置来猜证书。

**如何验收：** 干净目标 Mac 安装、首次启动、权限拒绝／重新授权、可选后端安装／卸载、模型下载与离线运行正常；系统签名／公证校验通过，不关闭安全机制；未选模态不强装所有运行时，升级保留原有用户数据。

**交付证据：** 安装包校验、签名／公证状态、干净机器验收和升级记录。

### 7.3 最终回归与发布批准

**干什么：** 对候选版本执行完整回归，整理 release notes、最低系统／硬件要求、已知问题和回退方式；用户明确批准后才执行对外发布。

**如何验收：** 候选包和验收 commit／校验值一致；所有必需步骤通过，无伪造的模型支持声明；安装、调用、取消、恢复、卸载关键流程通过；发布前有明确批准记录，发布后验证下载包和文档对应版本。

**交付证据：** 回归总表、候选包校验值、批准记录、正式发布说明。
